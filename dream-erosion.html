梦蚀 / 2D 叙事动作游戏

从一次眩晕开始，
让身体信息进入
玩家的行动。

叶夏天知道自己生病、暂时不能上学，却还不知道病情全貌。我希望玩家陪她确认安排、经历检查、整理不适，再带着这些尚未被解释的感受走进里世界。

我的职责 主策划 / 项目管理 / 音效设计

阶段
可运行 · 开发中
类型
叙事动作 / 表里世界
工作重点
医院流程、身体记录、行动反馈
医院探索身体记录表里衔接音效反馈结果与复盘

01 / 医院探索

每到一个地方，
都多知道一件事。

医院有楼层、材料、工作人员和检查流程。我的设计问题是：怎样让玩家知道下一步去哪，同时保留主角对自身处境的有限理解？我把第一章的行动串在病房、采血区和 MRI 区之间，让材料、身体变化与场景交互逐步提供信息。

  1. 016F · 确认安排

    打开背包，阅读住院单与检查单，知道要去哪里。

  2. 02走廊 → 2F · 经历变化

    途中出现眩晕，再完成登记与采血，留下需要整理的不适。

  3. 03回到病床 · 整理记录

    在安静的停顿中打开手机，确认经历，决定是否提交。

  4. 04B1 · 接受检查

    报到、准备 MRI，由现实检查过程衔接里世界。

主线材料与生活细节，承担不同作用。

医院流程用住院单和检查单推进；日记、演出票等物件留作可选信息。前者回答“接下来要做什么”，后者补充“她原本怎样生活”。这个取舍让任务保持清楚，也给愿意停下来观察的玩家留下空间。

02 / OSEC 身体记录

“我有点晕”，
可以怎样说得更清楚？

OSEC 是主角手机中的身体记录 App。我用走廊中的一次眩晕作为最小例子：先让事件发生，再整理时间、情境、感受和动作。玩家接触到的是自己刚刚经历过的内容，能够理解每条记录从哪里来。

上方是依据设计与 Godot 记录内容整理的说明图；9 月 13 日是剧情日期。

把决定留给玩家：确认之后，保存还是提交？

记录先等待本人确认，再进入保存或提交。两种选择表达不同意愿；先保留记录，也可以继续医院流程。OSEC 整理已知事实与待问问题，解释与后续回应交给医护。

保存但不提交

把确认过的经历留在手机里，供自己回看。

提交

把确认过的经历送入后续反馈流程，并清楚显示等待状态。

这个设计把一次“获得信息”拆成经历、理解与表达。真正需要玩家决定的，是哪些事实可以确认，以及是否把它们告诉别人。

03 / 表里世界

从身体经历出发，
让两个世界有理由相接。

表世界通过检查、等待和身体变化建立现实处境；里世界用有机地形、移动与战斗转译这些感受。两者的连接点需要发生在角色身上，因此我把手机的信息整理与现实场景的行动分开。

手机保留已知信息

记录、确认、保存和提交，帮助玩家带着信息继续行动。

医院推动真实进程

找到科室、沟通、报到与准备，由检查过程触发表里过渡。

这样的分工让玩家仍需亲自走进医院空间。里世界的黑童话则保留人物与环境中的矛盾，给后续重读留下余地。当前 Godot 路线已调整为 MRI 后直接进入里世界 1，早期序章教学属于此前的路线设计。

04 / 让动作被听见

挥出了武器，
也要听见有没有命中。

我在 FL Studio 中完成六项核心音效的采样、剪切、处理与导出，覆盖里世界行走、闪避、攻击命中、攻击落空、小怪死亡和使用药瓶。设计重点是让声音对应不同的动作结果。

命中 / 落空

区分已经发动攻击与攻击产生有效结果。

行走 / 闪避

让持续移动和一次短促位移拥有不同反馈。

死亡 / 用药

提示战斗目标结束，以及恢复行为发生。

六项交付已进入 Godot 运行资源和对应事件调用。其中攻击音效依据命中结果选择播放，让声音承担玩家判断行动结果的一部分。

05 / 阶段结果与复盘

下一步，先把这段经历
完整交到玩家手里。

项目从 Unity 转到 Godot，又经历了工程接管与重建。当前有可运行的 Godot 阶段版本；本次本地运行确认了从开场进入病房、移动、打开背包和阅读检查单。对照当前工程，身体记录也已包含确认、保存与提交逻辑。

完整章节体验仍待进一步验证，OSEC 的后续医护反馈与战斗数值联动仍待完成。这些是继续迭代要解决的内容。

把完成标准收回到一段连续体验。

这次经历暴露了引擎选择、工程交接和范围管理的代价。我的下一步会先锁定“病房确认安排 → 经历眩晕 → 整理记录 → MRI → 里世界”的短流程，观察玩家能否说清自己知道了什么、下一步为何这样做，再决定扩充哪些内容。

这次复盘留下的制作要求

迁移前先做最小验证，并保留可回退版本；交接时用实际能运行的内容确认进度；每次扩充前，先由一名未参与开发的人走完现有流程。这些要求用于下一阶段收敛，也把策划目标和工程交付放到同一个检查点。
