# 游戏体验快拆

**成稿格式。** 可见线索、玩家判断、可选动作和结果用一张短时间线表串起来。在成稿中实际给出图或表，哪怕只有两三行。正文解释图表能支持的取舍。

写完整拆解案时，先交付「游戏概览与可比作品」，用一句话介绍品类和玩家目标，用短流程说明一次典型游玩，再用小表给出有依据的可比对象、共同点、关键差异及其与本案的关系，最后限定版本、样本与主问题。单局部或已有上下文的续拆只补会影响判断的背景。

从一次具体的玩家体验出发，用当时可接触的信息、行为记录和游戏规则互相核对。交付一段按体验发生顺序的解释，让读者知道玩家当时能作出怎样的决定，以及这个决定如何改变下一步。

## 沿时间走一遍

1. **玩家当时在忙什么？** 交代局面和玩家想达成、弄清或避免的事。用自述或可观察行为支持对注意对象的判断。存在多个任务时，指出它们怎样竞争注意。
2. **信息什么时候到手？** 找到改变本次选择的线索，标出它在选择前、选择中还是结算后出现。区分界面显示过、玩家实际留意到、玩家理解了什么。同一条线索可在多个时刻有不同价值。按信息或判断改变的地方切段。
3. **这些信息能拼出什么选项？** 区分系统允许的操作和玩家当时有理由想到的做法。只有玩家能据此区分选项在成本、风险或后果上的差异，这项差异才能进入当下的权衡。可预判范围内的冒险也算有意义的选择。
4. **结果告诉他什么？** 交代实际行动、结算、玩家能从反馈知道什么，以及哪些仍需要自己归因。若有第二次相似决策，用它核对玩家有没有用上刚获得的信息。没有记录时，把下一步写成可能性。

## 用现有材料互证

- 有第一人称试玩感受就保留。以录像、截图或行为记录核对发生顺序，再用规则或结算核对真正的选项与后果。材料冲突时写清分歧。后来看说明、复盘时知道的事，归回它实际被知道的时点。
- 行为能说明玩家做了什么。注意、理解和选择理由分别寻找依据。只有画面或规则时，在可能的地方给出一种有依据的体验读法，并交代缺的是哪条玩家证据。单份样本的结论保留到这位玩家和当时的局面。
- 比较片段时，交代足以影响结论的差异。一次同时换了多个条件的结果，只能说明各自条件下观察到了什么。选一个最能改变当前判断的核查动作即可。
- 卡在注意、线索整合或结果归因时，按需读[心理学与教育学参考](references/attention-and-learning.md)。用研究提出具体解释，再回到这盘游戏的材料核对。

## 交付边界

默认交付一段短评。信息分两次以上到达、且先后影响结论时，可用少量分段或时间表。保留用户指定的篇幅、视角和格式。评审自有项目时，同样只拆用户圈定的体验片段。

拆到「当时能权衡什么、结算后能学到什么」即可收束。用户同时问设计意图时，用有明确出处的设计说明支撑，把从规则推回的目标写成待核假设。涉及主创长期取舍、玩家群体影响、完整课题验收或改版效果时，留下最具体的后续问题和相关证据，便于交给对应的研究或评审。

## 图示与图表

用简短时间轴或小表呈现「可见线索 → 玩家可能的理解 → 可选动作 → 结果」。标明哪些有录像或行为证据，哪些是规则推演。涉及系统、玩法或设计判断的段落应配能说明关系的图或表。一个简单表或流程足以表达时直接用它。图示表达同一组证据和判断，推演与待验证的连接标明状态。
