二级 · 机制与体验变化拆解

下载 SKILL.md ↓

成稿格式。 把机制因果写成箭头流程或 Markdown 对照表。在成稿中实际给出图或表，哪怕只有两三行。正文解释图表能支持的取舍。

写完整拆解案时，先交付「游戏概览与可比作品」，用一句话介绍品类和玩家目标，用短流程说明一次典型游玩，再用小表给出有依据的可比对象、共同点、关键差异及其与本案的关系，最后限定版本、样本与主问题。单局部或已有上下文的续拆只补会影响判断的背景。

从玩家体验出发，站到设计师的位置，解释既有的设计安排如何改变玩家当下在解决的问题，为什么在这里起作用，以及换掉它后还会不会发生同样的变化。以规则、信息、行动和反馈为依据，把解释限定在材料支持的版本和局面。

从哪里接

已有一级体验快拆时，接用其中的局面、当时能用的信息、玩家选择和实际后果。用户已给出这些材料时直接开始。缺少关键事实时，只补足本次比较所需的玩家局面。只有一个实测局面时，可用明确标注的反事实作另一边。

怎么拆

  1. 钉住变化。 写清变化前后，玩家分别在解决什么问题，哪条线索的重要性变了。区分行为、自述和推断。玩家做了不同动作，可能只是局势变了。玩家动作没变，也可能是选择理由变了。
  2. 对照两个局面。 优先比较同一规则跨阶段、同一局面下的两类玩家，或同一局面的单项变化。核对可能同时变化的条件，例如实际可行选项、信息时机与来源、资源和风险、玩家经验、当下目标、他人关系、上一轮反馈。只写对解释有影响的差异。
  3. 站在设计师这侧找变量。 顺着「设计安排 → 线索、成本或后果的变化 → 玩家当下的判断」解释作用。分清游戏在强调什么、规则让什么确实值得管、玩家自己想从中得到什么。查玩家有没有把新问题纳入权衡。即便最后的选择没变，他比较的东西也可能变了。需要时选读解释角度与证据，只用会改变解释或核查方式的角度。

可选方法 · MDA

要解释规则怎样变成对局体验时，用 MDA（Mechanics、Dynamics、Aesthetics）。M 写可核对的规则。D 写这些规则在游玩中怎样一起运转，以及玩家因此形成哪些行为或策略。A 写玩家可能获得的感受与体验。用「规则 → 对局中的行为与反馈 → 玩家体验」的小图或三列表表达。把 A 视为实际体验问题，区分设计者期望与玩家自述。规则与可复现结算支持 M 或 D 的一部分，体验观察用来核对 A。用户明确要求 MDA 时，呈现这三个对应项。 MDA 原论文

验证与互证

  1. 把证据贴到论点上。 按「设计条件变了什么 → 玩家当时能知道或做到什么 → 判断、选择或结果如何变化」逐环核对。规则、源码和结算证明机制允许或实际做了什么。界面与录像核对线索何时可见、玩家做了什么。玩家自述支持他当时如何理解与权衡。多份材料可以共同支持一条因果链，每份材料只承担它能证明的那一环。来自同一录像的截图与转述可以补充细节，仍是同一份观察。
  2. 试着区分竞争解释。 信息、成本、熟悉度或目标同时变化时，给最有力的替代解释。先找现有的可比局面。缺少实测对照时，用反事实或低成本验证写清固定什么、只改什么、看哪项行为或自述，以及什么结果会支持、削弱或暂时分不开这两种解释。标明对照已做还是待做。
  3. 处理反例和冲突。 材料说法不一致时，先核对版本、局面、玩家目标、时间点和证据来源。仍有分歧时，把它写进结论，说明证据支持到哪一环、哪一环仍是假设。只有机制证据时，玩家会不会注意、改选或获得某种体验，仍以预测表述。

交付到哪里

默认给出一条有条件的判断、两边的关键差异、直接支撑对应论点的证据，以及一个最能区分解释的对照或待验项。用户限定篇幅时优先保留对照与证据边界。反事实用于解释既有机制，具体数值、布置方案、完整改版和系统联验交给后续工作。

设计者公开解释过的目标可带出处引用。从规则反推的目标写作待核假设。团队长期取舍需要独立研究。引用访谈举例时，区分讲者的推演、游戏实际规则、开发团队意图。

例　两次进岔路都剩半格油。一次玩家担心回不去，另一次地图标出补给点，玩家去找指定矿石。补给可见可能让玩家由「能否折返」转为「能否抵达下一补给」，但熟路与采矿目标也改变了。固定同一路线、初始资源、熟悉度和任务，只改变补给位置能否提前知道，记录选路，并在选完后问玩家当时依据什么。若两边都按矿石位置选路，且说出的权衡相同，补给可见性的解释就弱了。半格余量相同，仍需核对实际油耗、路程与可达性。

图示与图表

用因果图或对照表展示「规则变化 → 信息或成本 → 判断 → 行为」，把每个箭头的证据状态落在对应一步。涉及系统、玩法或设计判断的段落应配能说明关系的图或表。一个简单表或流程足以表达时直接用它。图示表达同一组证据和判断，推演与待验证的连接标明状态。
