DESIGN / 01成长、奖励与地图关系
DESIGN QUESTION

这一战的收获，怎样改变下一战的打法？

我设计的不是彼此独立的奖励、遗物和地图，而是让战后选择回到弹射战斗：拿到什么、怎样搭配、走向哪里，都要产生下一次决策。

RULE MATRIX 对象 → 约束 → 玩家判断

技能 × 角色
技能类别与角色限制共同约束可用组合。先判断能否使用，再判断是否适合现有打法。
遗物 × 弹射
遗物不只增加数值，也会改变速度、撞击与击退表现。一次强化可能同时改变路径与碰撞收益。
资源 × 时机
普通攻击恢复蕾克拉，忍术消耗蕾克拉；金币用于商店选择。战斗内的释放时机，与商店中的购买取舍分开判断。
节点 × 路线
选择节点后锁定同层其他节点；出口必须指向真正可达的下一节点。选一条路，也意味着放弃同层其他机会。
BUILD EXAMPLE / 图鉴中的实际规则

断刀：更快的发射，
更弱的击退。

发射速度 ↑撞击 / 击退力度 ↓

这让遗物选择不只是“哪个数值更大”：我的组合更需要速度，还是需要把敌人推到下一次碰撞的位置？

DESIGN CHECK / 规则检查情境

一次胜利，不能变成多次收益。

检查路径：胜利 → 领奖 → 打开背包 → 返回。

应保持：已领取奖励仍为已领取；返回不能再次发奖，也不能解除已选路线对同层节点的锁定。

若返回就能重领，成长来自重复操作，而非战斗与选择，路线的取舍也会失效。

MY DECISION

把成长入口，连同退出条件一起定义。

我主导技能分类、角色限制、奖励、商店、遗物与路线约束；程序反馈 QA 问题，我修改规则，并与程序和 ChatGPT 商讨边界后继续迭代。

设计取舍：更多成长入口带来更多组合，也增加了结算与返回时需要保持一致的状态；收益、领取状态和路线进度必须一起考虑。

DESIGN / 02碰撞、回合与状态边界
DESIGN QUESTION

一次碰撞之后，谁受影响，什么时候轮到下一步？

弹射加入忍术后，命中不再只意味着扣血。我把目标、资源、穿透、击退和限时状态拆开定义，让连续碰撞可以形成组合，又不把回合卡在中途。

RULE MATRIX 触发 → 约束 → 收尾

忍术准备
选择技能时检查使用条件与资源；未满足条件，不能当作已生效。把“选中”与“实际触发”分开，避免无效选择改变战斗。
接触对象
撞墙、命中敌人、敌人之间的碰撞需要分别判断，不能套用同一种伤害。可形成连击，不等于允许错误的友军伤害。
特殊状态
穿透、击退与重新索敌会改变后续接触的含义；状态退出后应恢复对应判定。既考虑第一次命中，也考虑撞墙和二次碰撞。
回合结束
限时效果到期后结束；行动完成或无法执行，都要能进入后续流程。不能只在“正常命中”这一条路径上交还操作权。
SKILL EXAMPLE / 技能库中的实际规则

“握握手，握握双手”
把命中变成一段状态。

首次命中→抱起并带动→结束抱摔

图鉴描述了首次命中后的抱起、继续瞄准、时间结束后的抱摔，以及范围伤害和眩晕。设计对象因此从一次伤害，变成进入、持续、退出都有条件的动作。

DESIGN CHECK / 规则检查情境

没有打中，也必须结束行动。

异常条件：敌人没有可用攻击路径。如果只在命中后结束行动，回合可能一直等待。

规则要求：重选目标或跳过本次行动；两条分支都要释放行动占用，进入后续流程。

验收重点：目标不可达、路径失效与正常完成，都必须有结束出口；不能让一次行动阻塞整个回合。

MY DECISION

把“技能有效果”推进到“规则能闭合”。

我主导资源、触发对象、状态与例外规则的拆解，根据程序的 QA 反馈修改边界，再共同讨论并验证。

设计取舍：穿透、击退和连击带来组合空间，也扩大异常分支；增加一种效果，就要同时考虑它的冲突与结束条件。

DESIGN / 03界面状态与返回路径
DESIGN QUESTION

离开一个界面后，玩家能回到原来的那一步吗？

暂停、设置、背包不应只是能打开的页面。它们需要记住玩家从哪里进入、哪些状态仍然保留，以及什么时候才真正恢复战斗或继续推进。

RULE MATRIX 入口 → 保留状态 → 返回目标

暂停 × 战斗
打开覆盖层时保留战斗并停止推进；进入设置不意味着已经恢复战斗。关闭次级页面与“继续游戏”是不同动作。
设置 × 来源
设置页可以由不同入口打开，返回目标应跟随来源，不能固定指向地图或标题。复用页面，不能丢掉玩家进入它之前的上下文。
背包 × 奖励
从奖励进入背包后，返回需要接回原流程；配置变化与领取状态分别保留。离开领奖界面，不等于重新开始一次结算。
触控 × 确认
手机没有 ESC，需要可见的暂停入口；小屏奖励卡采用安全区内的单卡聚焦交互。滑动查看与确认选择分开，避免误领或看不到按钮。
RETURN CONTRACT / 相同页面，不同来路

“返回”应当接回玩家，
而不只是关掉窗口。

从标题进入设置
设置 → 标题
从暂停进入设置
设置 → 暂停 → 继续游戏

暂停返回链更长，但保留了明确的恢复入口；少一次点击，不应以意外恢复战斗为代价。

DESIGN CHECK / 规则检查情境

返回时，接回原来的那一步。

重点检查：暂停进入设置后能否返回暂停；奖励进入背包后能否接回领取流程；手机战斗中能否找到暂停入口。

验收边界：不越级跳页，不在菜单中偷偷推进战斗；轮播手势不触发确认，小屏不裁掉关键按钮。

MY DECISION

先定义流程，再一起补全状态。

这部分由我和程序共同完成：我给出界面与流程大纲，程序追问实现边界，双方补齐返回路径、暂停与移动端交互。

设计取舍：复用设置、背包等页面可以减少重复界面，但需要保留来源和当前进度；方便开发不能替代正确的玩家路径。

03 HUMAN × AI ITERATION

我把规则变成具体任务，跟着运行反馈继续修改。

  1. 01定义选择与状态

    写清触发对象、资源消耗、效果冲突和结束条件。

  2. 02与程序对齐任务

    讨论可行性，把问题转成可执行的修改要求。

  3. 03推进实现

    协商范围，决定优先级，再由工具执行代码与构建。

  4. 04带着反馈返工

    从运行报错、手机操作和现场表现回到规则修改。

LOGIC

为特殊效果补齐收尾

穿透、敌方行动与地图连通涉及不同状态；我根据 QA 反馈继续拆解触发、冲突与退出条件。

RUNTIME

处理运行时限制

数组越界、nil 错误与 Lua 局部变量上限持续占用返工时间，系统扩张也提高了实现成本。

MOBILE

把操作放到手机上

继续修正横竖屏、角色尺寸、暂停入口与旧二维码 manifest 失效问题。

VISUAL

视觉反馈没有追上系统扩张

现场玩家对特效爽快感有明确期待；工期和技术限制下，活动版本没有充分补齐这部分体验。

AUDIO WORKBENCH

让声音对应玩家动作。

角色与技能配音由我和程序两人真人实录；碰撞音效由我采样。我根据角色选择、技能点击、弹珠碰撞和撞墙等行为定义触发位置，并完成最终听感验收。

WHAT REMAINS

范围增长速度超过了验证速度。

三章地图、多角色、技能、遗物、词缀、商店与评分系统在 48 小时内快速叠加，带来状态复杂度、单文件局部变量上限和反复返工。活动版本同时没有充分补齐玩家期待的爽快视觉反馈。

复盘建议：核心循环成立后冻结主系统，用剩余时间强化一个角色、一章内容、少量可组合技能的手感与稳定性。

TAKEAWAY / 可迁移的方法

新增一个效果，同时定义它何时结束。

  • 拆规则：把玩家选择写成条件、状态变化与收尾。
  • 控范围：核心循环成立后冻结主系统，为手感和稳定性留时间。
  • 推交付：把程序与真机反馈转成下一项明确修改。
