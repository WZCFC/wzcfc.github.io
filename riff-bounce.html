01 ORIGINAL HYPOTHESIS

原型还没试清楚，制作工具已经长了出来。

最初想把跑酷、碰撞鼓点与音乐生成关卡连在一起。后续七键版本逐渐依赖制谱、编辑器和偏移校准；在 48H 工期里，玩法探索和工具制作开始争夺同一份时间。

WHAT MADE IT INTERESTING

把操作、声音与内容生成连在一起。

  1. 01

    玩家行为层角色持续移动，玩家用跳跃和换绳控制跑酷节奏。

  2. 02

    物理反馈层多边形内的鼓槌 / 小球碰撞边界，触发不同鼓采样。

  3. 03

    内容生产层进一步设想用 MIDI 把音乐数据转换为关卡。

事实范围这些内容支持“尝试连接这些环节的原型假设”；旧版联动、可玩程度和可见失败表现尚未确认。

02 VALIDATION GATE

剩余工期里，最值得试清的是哪段玩法？

LENS / 01

先隔离最有价值的反馈关系。

最初设想把跑酷操作、碰撞鼓点和 MIDI 关卡生成联系起来。我的复盘是：应先用最小原型试清输入与声音的关系，再决定是否需要自动生成内容。

  • 操作反馈
  • 声音反馈
  • 内容生成设想

LENS / 02 · 复盘判断

制谱与校准成为新的制作负担。

后续七键版本隔离了旧跑酷和物理鼓机，却继续增加音频转录、编辑器、偏移校准和变速谱。调试对象越多，越难单独判断核心操作是否有趣。

  • 核心乐趣难隔离
  • 调试对象过多
  • 交付风险继续上升

LENS / 03

把目标收回一个可以交付的战斗成长循环。

我参与取消 JSON / MIDI / 谱面与音乐时钟驱动，要求保留 Boss、HP、Ripple、共振和成长。通过独立出球继续推进，把时间集中到输入、判定和战斗反馈。

  • 先完成循环
  • 再验证手感
  • 集中剩余工期
DECISION PRINCIPLE

先列出本轮必须试清的输入、判定与反馈，再决定哪些模块值得继续投入。

03 CUT / KEEP / REBUILD

取消音乐驱动依赖，
保留战斗与成长的验证目标。

CUT / DECOUPLE

解除高风险依赖

  • 物理鼓机不再承担核心循环
  • MIDI / 谱面 / BPM / PPQ 不再驱动玩法
  • 音乐时钟与战斗时钟解耦

KEEP / REUSE

保留战斗与成长

  • BGM 独立播放的方向
  • Boss、HP 与反馈框架
  • Ripple、共振、XP 与局内强化

REBUILD / VALIDATE

收敛后的玩法

  • 要求实现随机出球与时机判定
  • 要求配置三档难度与固定随机种子
  • 要求提供运行时参数控制；BGM 以独立播放为目标
随机出球→ 时机判定→ Ripple / 伤害→ XP / 强化选择↺

01 / 失误

让工具链先于核心乐趣扩张。

复盘中，我把主要问题归结为：玩法还没试清，制谱、校准和编辑器已经成为新的交付对象。一次调整会牵动更多模块。

02 / 代价

转向保住交付，也压缩了打磨时间。

停止音乐驱动依赖后，仍需重建输入与战斗循环；活动版本留下了表现素材、手感和难度方面的不足。

03 / 下一次

先限定本轮要回答的一个问题。

先做最小的输入与反馈原型。只有它值得继续玩，才为它增加自动内容生产和编辑工具。

04 / 可迁移方法

把转向写成取消、保留、重建。

和程序讨论具体模块及依赖，再确定最低交付。方向变更需要落到任务清单，才能让团队继续行动。
