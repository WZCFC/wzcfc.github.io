四级 · 系统还原与联动拆解

下载 SKILL.md ↓

成稿格式。 用系统关系图标明传递方向、触发条件和缓冲路径。在成稿中实际给出图或表，哪怕只有两三行。正文解释图表能支持的取舍。

写完整拆解案时，先交付「游戏概览与可比作品」，用一句话介绍品类和玩家目标，用短流程说明一次典型游玩，再用小表给出有依据的可比对象、共同点、关键差异及其与本案的关系，最后限定版本、样本与主问题。单局部或已有上下文的续拆只补会影响判断的背景。

解释几套系统各自做什么、怎样配合，以及玩家为什么要把它们放在同一次计划里考虑。从一个局面、一条现有规则、两套看起来相似的系统或一项改动切入。玩家体验、机制解释、设计判断与系统联动可在同一篇分析里衔接。沿着会改变结论的连接展开。

1. 还原各系统怎么运转

沿用游戏内名称，或用清楚的功能名。说明各系统管什么，写出「起始条件 → 谁在什么时候作决定 → 规则如何结算 → 结果进入哪里」。优先核对正常操作、同版本规则与真实结算。关键数值、单位、时序、存档状态按材料确认。

优先用小图表示。资源用产出、库存与消耗，任务或权限用状态与触发，玩家策略用选项、代价与后果。用箭头标出实际流动的东西，例如食材、资格、时间窗口或信息。每条重要连接能说清谁产出、谁使用、何时起效、影响哪次决定即可。

可选模板 · 常规系统拆解清单

当用户要一份能交接的系统拆解，或者明确要求「拆解八股」时，可用下列结构梳理资料。按研究问题选用必要项，缺失或无关的字段从成稿省略。整案先用全局入口的游戏概览与可比作品开头。

检查项 写到什么程度
系统定位和玩家目标 系统在整局的位置，玩家在这里解决什么问题。
入口与前置 谁在什么时候进入，需要怎样的状态、资源或解锁。
输入、规则与输出 画「输入 → 判定 → 结算」，标清成本、状态变化、反馈和可查参数。
玩家选择 在什么信息下有哪些可行选项，代价会影响哪一手或下一轮。
资源循环与联动 产出去哪、谁消耗、怎样回流，哪些系统会接住或放大影响。
边界与异常 门槛、失败、取消、重置，以及决定结论的边界状态。
证据与验证 按版本标出处，区分规则、观察、推断和待验项。

宏观看系统位置与循环，中观看规则条件与体验反馈，微观只下钻到会改变判断的参数。流程、状态和对照优先用图表，正文解释影响玩家决策的那条连接。

2. 解释这些系统为什么要这样配合

先写每套系统各自让玩家判断什么，再写合在同一局面后，玩家多了哪项值得做的权衡。查一边是否给另一边提供目标或可行条件，是否争用同一份资源，是否让代价转移，或是否给对方提供退路。检查看起来相似的规则是否各自留下了不同的玩家决定。若两边只是同时变化，核对是否来自同一个上游条件。

按实际时序追到会改变设计判断的一步。可能是一个系统改变另一个系统的可行选项，也可能是两套约束共同改变了一次选择，或本轮的结算改变了下一轮的目标、能力和代价。解释配合的作用、支撑条件和代价。主创意图用有出处的设计记录或公开表述另行标明。

3. 分开写连接方式、影响大小和证据

  • 连接方式。 写清上游变化是直接改变了下游规则或状态，还是要等玩家看到、理解并改计划才传下去。若只有在稀缺、特定进度或某项门槛下才传递，写明条件。
  • 影响大小。 描述具体局面里变了哪些选项、数值、行动或结算，影响何时出现、持续到哪一轮。查门槛是否放大影响，库存、替代来源、备用路线或自动处理是否接住影响，以及代价最后落在哪。把一条路当替代前，先查它能否完成同一个目标，是否还受同一门槛约束。
  • 证据到哪一步。 把规则推导、实际结算、玩家行为、自述和待验预测放在各自支撑的连接上。直接依赖和影响被缓冲可以同时成立。材料少时给有条件的定性判断，说明哪项观察会改变它。

4. 用对照检验，再给设计判断

用户只问现状时，先交付完整的系统解释。必要时用移除、交换或补偿一条规则作为反事实，核对哪些玩家判断会保留、消失或改变。用户给了改动时，比较原安排和新安排，优先隔离关键变量。两种任务都先查可用的现有对照，再按需给一个最小待验项。至少说明本系统先变什么、下游在哪一步可能变，以及出现什么会让自己改判。若存在回流，再查下一轮。

交付小图或因果链、系统配合带来的玩家决定、主要代价和证据、以及设计判断。可建议保留、调松或换一种连法，给出适用条件。用「我倾向」「我的初判」「下一步我会核对」直接讲清理由及待检验的部分。

图示与图表

用有方向的系统关系图说明变化经由什么、在哪些条件变强、在哪里被接住。反事实比较可以用对照表。涉及系统、玩法或设计判断的段落应配能说明关系的图或表。一个简单表或流程足以表达时直接用它。图示表达同一组证据和判断，推演与待验证的连接标明状态。
